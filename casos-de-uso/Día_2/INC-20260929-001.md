## 2. Resumen ejecutivo

Se detectó la creación de un nuevo usuario (`testuser`) en el endpoint `endpoint-lab` (EndeavourOS). La alerta fue generada por el agente de Wazuh (regla 5902, nivel 8, técnica T1136) y enviada al servidor SIEM. Tras la investigación, se confirmó que la acción fue realizada por el propio analista (`Jaq`) mediante `sudo` como parte de una prueba controlada para validar la capacidad de detección de Wazuh. No hubo actividad maliciosa.

## 6. Análisis

**Hipótesis evaluadas:**
1. **Creación maliciosa de usuario (descartada):** El usuario fue creado por `Jaq` (el analista) mediante `sudo`, no por un actor externo. Los logs muestran la IP de origen como localhost/terminal SSH.
2. **Error de configuración (descartada):** No hubo scripts automáticos ni tareas programadas que crearan el usuario.
3. **Prueba controlada (confirmada):** La acción fue intencionada para validar la regla T1136 de Wazuh.

**Razonamiento:**

Wazuh detectó correctamente un cambio en `/etc/passwd`. La técnica T1136 es utilizada por atacantes para persistencia, pero en este caso el contexto (usuario `testuser`, ejecución manual con `sudo` por `Jaq`, horario de laboratorio) indica actividad legítima. La inteligencia de amenazas de Wazuh (que menciona grupos rusos) es contextual y no aplica a este caso.

## 10. Lecciones aprendidas

- La importancia de distinguir entre el endpoint (donde ocurre la acción) y el servidor SIEM (donde se visualiza la alerta).
- En Arch/EndeavourOS, los logs de autenticación se consultan con `journalctl`, no con `/var/log/auth.log`.
- Wazuh proporciona contexto de inteligencia de amenazas, pero el analista debe evaluar el contexto local.
- `journalctl` sin filtros de tiempo puede ser muy lento; siempre usar `--since` o `--until`.
